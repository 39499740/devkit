### 1. 四个数据结构工具（T42–T45，均归入「数据格式」，分类计数 4 → 8，工具总数 41 → 45）

| 编号 | 路由 | 能力 | 引擎位置 |
| --- | --- | --- | --- |
| T42 | `/tools/sql-format` | MySQL / PostgreSQL / SQLite 方言，缩进 2/4，关键字大写开关，格式化 / 压缩；方言差异体现在注释语法、引用符建议与语法提示 | `app/utils/sql.ts` |
| T43 | `/tools/xml-toolbox` | 格式化 / 压缩 / XML ↔ JSON / XPath 查询四种模式；命名空间前缀映射；匹配列表 + 源文本高亮定位 | `app/utils/xml.ts` |
| T44 | `/tools/jsonpath-query` | JSONPath 与 JMESPath 求值，输出结果 JSON 与匹配路径列表；可接收其他工具传来的 JSON | `app/utils/jsonpath.ts`、`app/utils/jmespath.ts` |
| T45 | `/tools/json-schema` | 从 JSON 推断 Schema（Draft 2020-12 / Draft-07 + 严格模式）与按 Schema 校验，一次收集全部错误并给出 JSONPath + Schema 位置 | `app/utils/jsonschema.ts` |

设计稿里的样例数据全部沿用，校验结果与设计稿逐条一致：

- T44 示例 `$.store.book[?(@.price < 100)].title` → 3 项，路径 `$.store.book[0]/.book[1]/.book[3].title`。
- T45 示例 → 3 个错误：`$.user.email` 缺少必填字段、`$.user.age` 应为 integer 当前为 string、`$.orders[1].amount` 应为 number 当前为 null。

**已实现的边界（不夸大）**

- SQL：只做词法切分 + 子句级重排，不是完整语法解析；不重写标识符与字面量，与保留字同名的标识符只提示引用符建议。
- XML：走浏览器原生 `DOMParser` / `document.evaluate`（XPath 1.0）；XML → JSON 时属性写 `@name`、文本写 `#text`、同名子节点合并为数组。
- JSONPath：支持子属性、下标、通配、递归下降、切片、联合与 `[?(@.a > 1)]` 过滤；JMESPath 支持字段、下标、切片、通配、扁平化、过滤、管道、多选与常用函数（`length`/`sort_by`/`max`/`join` 等），未实现的语法与函数会明确报错而不是静默返回空结果。
- JSON Schema：Draft 2020-12 子集（type / enum / const / required / properties / additionalProperties / patternProperties / items / prefixItems / minItems / maxItems / uniqueItems / contains / 字符串与数值约束 / allOf / anyOf / oneOf / not / if-then-else / 本地 `$ref` / dependentRequired）。严格模式 = `format` 断言计为错误，关闭时仅提示。

### 2. 处理流程（S11 / S12）

- 新路由：`/workflows`（流程列表 + 最近运行 + 隐私说明条）、`/workflows/[id]`（三栏：步骤库 / 步骤链 / 当前步骤）。
- 步骤库 8 个步骤：Base64 解码、JSON 格式化、JSONPath 提取、JSON 转 Java、JSON Schema 校验、URL 解码、JSON / YAML 转换、下载结果（`app/utils/workflow.ts`）。
- 三条默认流程与设计稿一致：订单快照解析（4 步）、配置格式互转（3 步）、接口响应校验（3 步）。默认 id 固定并预渲染，刷新后仍能打开编排页。
- 数据只在页面内存中传递：`useState` 保存，刷新即回到默认流程；不写 localStorage / IndexedDB，运行记录里不含任何输入数据。
- 步骤链支持单步运行、上移 / 下移 / 删除，当前步骤显示真实日志、输出大小与耗时；「添加自定义步骤」按设计保留但禁用（不执行任意代码）。
- **不编造历史记录**：最近运行列表在没有运行时显示空状态文案，与设计稿里的示例记录（12 次运行）不同。

### 3. 「发送到…」路由弹层（G09）

`app/components/SendToMenu.vue` 由下拉菜单升级为中心弹层：

- 传递摘要按真实内容生成（`JSON 对象 · N 个字段 · N 行 · 体积`）。

### 4. PWA（S13 / G10）

- `app/components/PwaInstallButton.vue`：首页页头的「可安装为桌面应用」徽标 + 安装引导弹层；安装条件（manifest / Service Worker / 浏览器安装入口）按运行时真实状态逐项检查，不支持自动安装时给出手动步骤（Chrome / Edge 与 Safari）。

修复过程中由测试额外发现并修掉的三个真实缺陷：

1. **整数被推断成 number**：`inferNode` 用了只服务错误文案的 `actualType()`（不区分 integer），导致「从 JSON 生成 Schema」永远生成 `number`。
2. **utils 依赖 Nuxt 自动导入**：`xml.ts` / `workflow.ts` 里的 `errMessage` 来自 composable 自动导入，脱离 Nuxt 直接跑就报 `errMessage is not defined`；已收敛到 `app/utils/errors.ts` 并显式 import。
3. **接收端未声明消费方**：`useTransfer.deliver()` 会绑定目标，而 7 个接收工具调用 `take()` 时没带自己的 slug，导致带目标的载荷永远取不到（浏览器端到端复核发现）。

1. **历史记录不造假**：S11 设计稿展示了 12 条运行记录与「2 分钟前 · 成功 · 38 ms」等卡片脚注，实现改为真实记录 + 空状态文案。
2. **流程输入区**：设计稿的流程输入来自其他工具传递；实现额外提供一个「流程输入」文本框，便于手动粘贴与调试，传输语义不变。
3. **步骤链操作按钮**：设计稿只有单步运行按钮，实现补充了上移 / 下移 / 删除（没有这些无法真正编排）。
4. **添加自定义步骤**：按设计保留按钮但禁用，避免在页面内执行任意代码。
5. **页头收藏按钮**：处理流程页未放收藏星标（收藏体系以工具 id 为键，流程不在其中），改为返回列表入口。
6. **步骤库图标**：设计稿每个步骤有独立图标，实现统一用中性图标，避免为文案猜测图标语义。
