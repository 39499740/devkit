## 3. 文案差异与真实性说明

1. **H1 用「工具不存在或链接已失效」**：设计页头标题是「工具不存在」，但任务必做第 2 条明确要求 404 显示「工具不存在或链接已失效」。二者合并，H1 采用任务要求文案并放在设计的页头位置；设计页头副标题、空状态标题等其余文案保持原样。空状态标题仍为设计原文「找不到这个工具」。
2. **状态码后缀不回显地址**：设计示例为「HTTP 404 · /t/unknown-tool」，但设计注释明确「不根据用户输入回显地址内容」。实测 Nuxt 对 `/nope` 的 `statusMessage` 为 `Page not found: /nope`，若直接拼接会把用户地址回显进页面。因此状态码统一渲染为 `HTTP {{statusCode}}`，不带路径。这样既符合注释，也避免把无效地址当数据展示。
3. **工具数量 41 真实**：`toolCount = tools.length = 41`，与设计文案「41 个工具」完全一致，直接动态取真值（未写死）。
4. **搜索框是「打开全局搜索」的按钮，不是本地输入框**：设计注释说明本页为静态页、参数联动为无、搜索框内容不写入本地存储。项目里真实可用的搜索是全局命令面板（⌘K / Ctrl K，`usePalette`）。因此把它实现为样式等同搜索框的按钮，点击后回首页并打开命令面板，而不是做一个不落地的本地过滤框。文案「搜索工具名称、缩写或别名…」保留设计原文，`aria-label="打开全局搜索"`。
5. **「本地处理」标记指向 `/privacy`**：项目确有隐私说明页，链接真实可达。

## 4. 404 与 500 分支差异（不伪造错误细节）

- 404（`statusCode===404`）
  - H1：工具不存在或链接已失效
  - 副标题：链接可能已失效，或该工具尚未发布。
  - 空状态：找不到这个工具 / 上述设计说明（含真实 41 个工具）
  - 说明区：仍然找不到？ + 设计与真实功能一致的引导
  - 图标与头部用 `--cat-time-soft`（设计色）
- 非 404（如 500）
  - H1：页面出现了错误
  - 副标题：`error.statusMessage`（真实），无则「页面在加载或渲染时发生了错误。」
  - 空状态：这个页面没能正常加载 / `error.message`（真实），无 message 时回退 `statusMessage`，再回退「页面没有携带更多错误信息，可以返回首页或刷新重试。」
  - 说明区：还是打不开？ + 重试/记录错误信息引导
  - 图标与头部用 `--error-soft` / `--error`
  - 不对错误细节做任何编造；无信息时明确说明「没有携带更多错误信息」。

## 5. 可访问性

- 所有动作均为原生 `<button>` / `<a>`（NuxtLink），可 Tab 聚焦；全局 `:focus-visible` 2px `--accent` 描边生效。
- 修复了初版里 `<NuxtLink><DkButton></NuxtLink>` 造成的嵌套交互（一个动作两个 Tab 停靠点）：改为单一 `NuxtLink.err__link-btn`，样式对齐 `DkButton` 次级按钮。
- 深色主题下把状态码、搜索占位、`Ctrl/⌘ K`、「常用：」等 11–12.5px 小字由 `--text-tertiary`（≈3.8:1）提升为 `--text-secondary`（≈7.3:1，AA）；装饰性大图标仍用 `--text-tertiary`（图形 3:1 门槛，≈3.8:1 通过）。
- 页面保留 `main`/`header`/`nav` 语义地标（由 layout 提供）。
