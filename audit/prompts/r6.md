## 必须做的事（用命令得出证据）
1. **构建/类型/lint**：
   - `cd devkit && npx nuxt typecheck`（若不可用则 `npx vue-tsc --noEmit`）→ 记录全部类型错误；
   - `cd devkit && npx nuxt build`（或 `npm run build`）→ 记录构建错误/警告；必要时 `npm run generate` 检查静态产出；
   - 检查是否有 TS `any` 滥用、未使用变量、死代码（可用简单 grep 佐证）。
2. **SSR 安全**：搜索所有在 setup 顶层访问 `window/document/localStorage/navigator/crypto` 的地方（`grep -rn`），逐一验证是否会导致 SSR 报错；用 `curl -s http://localhost:3000/<route> | wc -c` 与 console 日志交叉验证；检查 `<ClientOnly>` 使用是否必要。
3. **composables/utils 正确性与边界**：
   - `app/utils/json.ts` 大整数安全实现是否真的正确（自己用 node 造用例：19/20 位整数、`1e21`、重复键、负数、`-0`、超长小数、Unicode 转义）；
   - `app/utils/bytes.ts` 的 hex/base64/text 转换边界（奇数长度、非法字符、BOM、非 UTF-8 字节、空输入）；
   - `useToolRun` 状态机（idle/ok/error/stale/running）是否可能出现“结果已过期但仍可复制”或“失败后 status 显示成功”；
   - `usePrefs/useFavorites/useRecent` 的 localStorage 持久化：是否存了输入正文/密钥/Token（真实性红线）；是否处理了 localStorage 不可用/超限。
4. **运行时健康**：用 `python3 audit/tools/probe.py` 跑主要路由，汇总 console error/warning、pageerror、失败请求；检查是否有资源 404（如字体、图标、favicon）、是否有内存/定时器泄漏（`setInterval`/`addEventListener` 未清理，grep 后人工确认）。
5. **安全性**：`v-html`/`innerHTML` 使用点（grep）是否可控；SVG/HTML 工具是否可被 XSS；是否有 `eval`/`new Function`；外链是否 `rel=noopener`。
6. **可访问性**：主要页面用 probe 的 a11y 字段 + 人工检查：按钮无名称、图片无 alt、表单无 label、焦点可见性、键盘可达（命令面板 ⌘K/Esc/方向键、弹层焦点陷阱）。
7. **性能**：首页/工具页首屏资源体积（`curl -s -o /dev/null -w` 或看 build 产物 .output 大小）；41 个工具组件是否被拆包（工具页是否全量打包导致首页过大）；是否存在重复依赖。
8. **一致性**：`devkit/README.md`/`FOUNDATION.md` 声称的能力与代码是否一致（例如 README 说 dev server 默认 3000 但 FOUNDATION 写 3100；声称的组件/能力是否存在）；`data/tools.ts` 的 tags/alias 与实际功能是否匹配。
